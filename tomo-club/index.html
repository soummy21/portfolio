Designing for Kids & the Classroom

Frictionless Onboarding Flow

Educational games fail if teachers spend half the period acting as IT support. Traditional account logins create severe friction and run into child data privacy constraints (COPPA/FERPA).

I designed an asymmetric entry model: educators configure custom match parameters and generate a single session ID, while students join instantly using ephemeral room codes and display names—requiring zero credentials or setup time.

Parallel Game Groups

  • Unified Session ID: The entire class connects via a single code, eliminating messy link distribution.
  • Dynamic Groups: The room automatically distributes incoming students into balanced 2-4 player groups.
  • Live Rebalancing: Teachers can swap students between groups, reassign slots, or adjust group sizes before launching all games simultaneously.
Live Teacher Moderation: Real-time game control such as pause, play, restart and group oversight.

Educator Moderation & Spectator Controls

  • Multi-Instance Spectating: A central observer view providing real-time visibility across all active match groups from a single dashboard.
  • Global Controls: Instant room-wide pause controls that freeze all active simulations when the educator needs to deliver classroom instruction.
  • Individual Group Controls: Granular controls to force-advance stalled student turns and resolve deadlocks without interrupting other groups.

Running Multiple Networked Simulations In Parallel

Architecture Breakdown

To run up to 8 independent match instances (scaling to 32 simultaneous students) within a single Unity scene without packet pollution or gameplay overlap, I architected a hierarchical GroupManager → Group → Game structure.

This topology completely isolates gameplay from networking. The Game Instance only resolves local logic, while the Group packages that logic and passes it to the GroupManager to be routed across the network.

Decoupled Architecture: Interfacing away the network layer from core gameplay
Network-Agnostic

The GroupManager interfaces with an abstracted network layer. While currently implemented with PUN 2, this decoupled architecture allows the backend to be hot-swapped to Fusion or Netcode without rewriting core gameplay logic.

Encapsulated Group State

Each group manages its own turn timer, lifecycle state (Active, Paused, Disconnected), and player membership. If one pod stalls or pauses, neighboring pods continue simulation uninterrupted.

Spatial & Camera Isolation

Each pod is partitioned into segregated scene coordinates and visual culling. Both student cameras and the teacher’s bird’s-eye spectator cameras track only their assigned pod's entities.

Live Viewport Separation: Student vs. Educator

The student’s localized view renders only their immediate view or group view depending on the game type, while the educator’s spectator view renders a full-map overlay composed of telemetry from every active group.
